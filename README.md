# askback24 — 면접 역질문 준비 (시연 사이트)

2026 고용24 AI 해커톤(팀 레인보우 가이즈) 2차 MVP다. 고용24 마이페이지를 닮은 **시연용 모의 화면**에 "면접 역질문 준비" 기능을 붙였다. 지원한 공고를 읽고, 구직자가 고른 기대·걱정으로 면접에서 회사에 물어볼 질문을 만든다. 1차 면접을 다녀오면 정리한 내용으로 최종 면접·처우 질문을 만든다.

> 실제 고용24가 아니다. 모든 화면 맨 위에 시연 띠가 있고, 회사·공고·인물(김00)은 모두 예시다.

화면은 고용24 틀(시연 띠·헤더·주 메뉴·왼쪽 메뉴·경로 표시)을 그대로 두고 역질문 화면 안쪽만 정리했다. 심사위원이 공공 사이트 화면에 익숙하다는 팀 합의(D-106)에 따른 것이다.

문서: 계획 [`docs/PLAN.md`](docs/PLAN.md) · 2차 계획 [`docs/PLAN-2.md`](docs/PLAN-2.md) · 3차 계획 [`docs/PLAN-3.md`](docs/PLAN-3.md) · 완료 기준 [`docs/ACCEPTANCE.md`](docs/ACCEPTANCE.md) · 결정 [`docs/DECISIONS.md`](docs/DECISIONS.md) · 디자인 기준 [`docs/DESIGN-REVIEW.md`](docs/DESIGN-REVIEW.md) · 시연 범위 [`docs/DEMO-SCOPE.md`](docs/DEMO-SCOPE.md) · 시험과 기준이 어긋난 것 [`docs/SPEC-ISSUES.md`](docs/SPEC-ISSUES.md) · AI 담당용 API 명세 [`docs/API-SPEC.md`](docs/API-SPEC.md)

## 실행 방법

Node 22 이상, npm을 쓴다.

```bash
npm ci
npx playwright install chromium   # 화면 시험을 돌릴 때만
```

### 시연용으로 띄우기 (가짜 응답 모드, 권장)

서버 함수 없이 브라우저 안에서 질문을 만든다. 시연과 시험은 이 모드로 한다.

```bash
npm run build:mock
npm run preview        # http://localhost:4173
```

고치면서 볼 때는 `npm run dev:mock` (터미널에 찍힌 `Local:` 주소, 보통 http://localhost:5173). Windows PowerShell 5.1은 `npm run dev -- --mode mock`의 `--`를 지워서 Vite가 `mock`을 폴더로 읽고 흰 화면(모든 주소 404)이 되므로 `dev:mock`을 쓴다.

다 본 뒤에는 띄운 서버를 끈다(터미널에서 Ctrl+C). 서버를 켜 둔 채로 화면 시험을 돌리면 4173 포트가 겹친다.

### 실제 모드

`npm run build` / `npm run dev`는 실제 모드다. 화면이 `POST /api/questions`(Vercel 함수, `api/questions.ts`)를 부르고, 12초 안에 답이 없거나 오류가 나면 미리 검수한 문장으로 대신 보여 준다. 로컬 `npm run dev`에는 서버 함수가 없으므로 늘 검수 문장으로 대체된다.

서버 함수 환경변수는 `.env.example`을 본다. 키는 `api/` 안에서 `process.env`로만 읽고, `VITE_`로 시작하는 변수에 넣지 않는다. `.env`는 커밋하지 않는다.

| 변수 | 뜻 |
|---|---|
| `LLM_PROVIDER` | `mock`(기본) · `remote`(AI 담당 서버) · `ennoia`(자리만). 모르는 값이면 `mock` |
| `AI_ENDPOINT`, `AI_API_KEY` | `remote`일 때 AI 담당 서버 주소와 키. 아래 「실제 AI 연결」 |
| `ENNOIA_API_KEY`, `ENNOIA_ENDPOINT` | 엔노이아 자리만 남아 있다. 엔노이아는 이번 범위에서 뺐고(D-110), 값이 있어도 부르지 않는다 |

### 고용24 공공데이터 다시 받기

화면·시험·빌드는 고용24 오픈API를 부르지 않는다. `data/real/*.json`에 미리 받아 둔 값만 읽는다. 다시 받을 때만 아래 스크립트를 쓴다.

```bash
npm run fetch:work24                  # 받아 둔 원본(.cache/work24/)이 있으면 다시 부르지 않는다
npm run fetch:work24 -- --only=ncs    # 일부만: ncs · job · codes · giants
```

- 키는 `.env`의 `WORK24_KEY_DUTY`(직무정보) · `WORK24_KEY_JOB`(직업정보) · `WORK24_KEY_COMMONCODE`(공통코드) · `WORK24_KEY_SMALLGIANT`(강소기업)에서만 읽는다. 키는 출력·캐시 이름·`data/real`에 남기지 않는다.
- 1.5초에 한 번, 한 번 실행에 200번 이하로 부른다. 오류 응답이 오면 그 자리에서 멈춘다. 너무 자주 부르면 IP가 막힐 수 있다.
- 받은 원본은 `.cache/work24/`(커밋 안 함)에 두고, 강소기업 명단의 회사명·사업자번호는 여기에만 남는다. `data/real`에는 개수만 적는다.
- Vercel에는 이 키를 넣지 않는다. 배포된 사이트도 API를 부르지 않는다.

### 시험

```bash
npm run build          # 타입 검사 + 빌드
npm run test:unit      # Vitest (shared/, api/, src/, scripts/)
npm run test:e2e       # Playwright, 데스크톱 1440 · 휴대폰 375 (Chromium)
npm run test:e2e -- --grep "S4-13"   # 특정 ID만
npm run screens        # 화면 캡처 → review/screens/*.png
npm run check          # 위 세 가지(build · test:unit · test:e2e)를 차례로
```

화면 시험은 `vite build --mode mock` + `vite preview`(포트 4173)를 스스로 띄우고 끝나면 끈다. 4173 포트가 비어 있어야 한다. 휴대폰 시험은 375×812로 돌고, 역질문 ③ 첫 화면 시험(F-02)만 390×844로 잰다. 처음 온 사람 안내는 시험 스위치를 켠 채 돌고 안내 시험(TR)만 끈 채 돈다(아래 「안내 끄기와 시험 스위치」, `e2e/README.md`).

`npm run screens`의 3차 밤샘 캡처는 이름이 `6-`로 시작한다(데스크톱·휴대폰 한 장씩): ① 공고 분석 로딩(`6-s4-first-1-loading`), 형광펜을 다 칠한 ①(`6-s4-first-1-drawn`), ② 도움말 팝업(`6-s4-first-2-help`, 데스크톱 말풍선·휴대폰 아래 시트), ③ 1차·최종 오른쪽 "전체 복사"·인쇄 상자(`6-s4-first-3-side`·`6-s4-final-3-side`), S1 서비스 안내 1·4단계(`6-s1-tour-1`·`6-s1-tour-4`).

### 안내 끄기와 시험 스위치

처음 들어온 브라우저에는 화면마다 처음 온 사람 안내(스포트라이트)가 한 번씩 뜬다. 첫 화면 S1에서는 사이트 기능 전체를 소개하는 서비스 안내(7단계), 다른 화면은 그 화면 안내(2~3단계)다. 본 화면은 이 브라우저에 `rq:v1:tour`로 남아 다시 뜨지 않는다. 안내를 막는 방법은 넷이다.

| 방법 | 하는 일 | "시연 초기화" 뒤 |
|---|---|---|
| 시연 도구 → **안내 끄기**(누르면 "안내 켜기"로 바뀜) | 어느 화면에서도 저절로 뜨지 않는다. 이 브라우저에 저장 | 풀린다(S1 서비스 안내부터 다시 뜸) |
| 안내 상자 아래 **다른 화면 안내도 그만 보기** | "안내 끄기"와 같다(지금 안내도 닫음) | 풀린다 |
| 주소 끝에 `?tour=off` (`?tour=on`은 다시 켬) | "안내 끄기"와 같다 | 풀린다 |
| 시험 스위치: localStorage `rq:test:tour-off` = `"1"` | 저절로 뜨는 것만 막는다. "이용 안내 다시 보기"처럼 사람이 누른 것은 뜬다. 시험 전용 | 그대로(초기화가 지우지 않는 키) |

화면 시험은 `playwright.config.ts`가 4173 포트에만 시험 스위치를 넣어 돌고, 안내 시험(TR)과 안내 캡처(`6-s1-tour-*`)만 스위치 없는 새 context에서 돈다. 손으로 켜려면 개발자 도구 콘솔에서 `localStorage.setItem('rq:test:tour-off', '1')`, 끄려면 `localStorage.removeItem('rq:test:tour-off')`. 심사·시연에서 안내를 확인할 때는 스위치를 켜지 않은 창(시크릿 창 등)에서 본다.

## 실제 AI 연결

질문 문장 쓰기와 1차 면접 답 판정은 AI 담당 서버가 맡는다. 우리 서버 함수(`api/questions.ts`)가 그 서버의 세 주소 `POST {AI_ENDPOINT}/v1/first-questions` · `/v1/final-judgements` · `/v1/final-questions`를 부른다. 요청·응답 형식, 응답 규칙, 실패 처리는 명세 [`docs/API-SPEC.md`](docs/API-SPEC.md)에 있다. 연결 코드는 `shared/providers/remote.ts`이고, 지금 배포는 가짜 응답 모드(`mock`) 그대로다.

| 환경변수 | 값 | 넣는 곳 |
|---|---|---|
| `LLM_PROVIDER` | `remote` (기본 `mock`) | Vercel 서버 함수 환경변수 |
| `AI_ENDPOINT` | AI 담당 서버 주소, `/v1/…` 앞부분(예: `https://ai.example.com`) | Vercel 서버 함수 환경변수 |
| `AI_API_KEY` | AI 담당 서버가 준 키. 우리 서버가 `Authorization: Bearer <키>`로 보낸다 | Vercel 서버 함수 환경변수(Sensitive) |

세 값은 Vercel 대시보드 → 프로젝트 → Settings → Environment Variables에 넣고, Preview(staging 미리보기)와 Production(main)을 따로 고른다. `VITE_`로 시작하는 이름에 넣지 않는다(화면 번들에 들어간다).

`AI_ENDPOINT`는 `https://`만 받는다(로컬 시험용 `http://localhost`·`http://127.0.0.1`은 예외). 운영(Vercel `VERCEL_ENV=production`)에서 `AI_API_KEY`가 비어 있으면 AI 서버를 부르지 않고 모두 검수 문장으로 낸다. 로컬·Preview는 키 없이도 부른다.

가짜 응답 모드에서 실제 모드로 바꾸는 순서(배포 전환은 세진이 정한다):

1. AI 담당 서버가 `docs/API-SPEC.md`의 세 주소를 만들고, `docs/api-examples/*-request.json`을 보내 `*-response.json`과 같은 모양이 오는지 확인한다.
2. Vercel Preview 환경변수에 `LLM_PROVIDER=remote`, `AI_ENDPOINT`, `AI_API_KEY`를 넣는다.
3. `vercel.json`의 `buildCommand`를 `npm run build:mock`에서 `npm run build`로 바꿔 staging에 push한다. 이제 화면이 `POST /api/questions`를 부른다.
4. staging 미리보기에서 질문을 만들어 본다. ③ 제목 옆 "가짜 응답 모드" 태그가 없고 질문에 "검수 문장" 라벨이 붙지 않으면 연결된 것이다. Vercel 함수 로그의 `[questions] … provider=remote … template=0`에서 `template=`이 0이 아니면 `issues=`(걸린 검사)와 `failure=`(오류·시간 초과)를 본다.
5. 문제가 없으면 Production 환경변수에도 같은 값을 넣고 main에 합친다. 되돌릴 때는 `LLM_PROVIDER=mock`(서버만) 또는 `buildCommand`를 `npm run build:mock`으로 돌린다.

AI 서버가 늦거나(9초) 오류를 내거나 응답 모양이 틀리면 우리 서버가 그 질문을 미리 검수한 문장(최종 판정은 단순 규칙)으로 대신하므로 화면은 멈추지 않는다. 로컬 `npm run dev`에는 서버 함수가 없어서 연결은 단위 시험(가짜 fetch, `api/_lib/remote.test.ts`)과 staging 미리보기로 확인한다.

명세의 예시 JSON(`docs/api-examples/` 6개)은 코드로 만든다. 규칙·데이터·가짜 공급자를 고친 뒤 아래 명령으로 다시 쓰고, 단위 시험(`scripts/apiExamples.test.ts`)이 파일과 지금 코드가 같은지 비교한다.

```bash
npm run api:examples   # docs/api-examples/*.json 6개 다시 쓰기(네트워크 없음)
npm run test:unit      # AS-03(예시 = 코드) · AS-07(remote 연결 계약)
```

## 시연 순서 (3~5분)

시작 전에 맨 위 시연 띠 오른쪽 끝의 **시연 도구 → 시연 초기화**를 누르면 지원 내역·선택·결과·안내 띠와 본 안내·공고 분석 로딩 기록이 처음으로 돌아간다(안내 끄기도 풀림).

처음 들어온 브라우저(또는 "시연 초기화" 뒤)에는 지원 내역 화면에서 사이트 기능 전체를 소개하는 **이용 안내**(7단계, 화면을 어둡게 하고 한 곳씩 비춤)가 뜨고, 다른 화면에 처음 들어가면 그 화면 안내(2~3단계)가 한 번 뜬다. 발표 중 안내 없이 보이려면 **시연 도구 → 안내 끄기**(다시 켜려면 "안내 켜기") 또는 주소 끝에 `?tour=off`(위 「안내 끄기와 시험 스위치」). 다시 보려면 안내 띠의 **이용 안내 다시 보기**나 시연 도구의 **안내 다시 보기**.

1. **알선/입사지원 내역** (`/mypage/applications`) — 고용24 표에 "면접 준비" 열(AI 라벨, 보라색)만 새로 붙였다는 점을 보인다. 회색 글자 메뉴·탭은 시연 범위 밖이다. 마우스를 올리면 "시연 범위 밖이에요"가 뜨고, 누르면 알림만 뜬다(시연 띠에도 적혀 있다). 휴대폰에서는 지원 건 목록이 검색 상자보다 먼저 나온다.
2. 1행 (주)OO소프트 **면접 역질문 준비** → ① **공고 확인**. 처음 들어가면 약 2초 동안 "AI가 분석한 공고를 펼치고 있어요"(공고 원문 확인 → 업무 카드와 맞춰 보기 → 확인할 곳 표시, 그 공고의 근거 인용이 하나씩)가 뜨고, 공고를 내려 보면 형광펜이 위에서부터 왼쪽→오른쪽으로 그어진다. 같은 지원 건은 두 번째부터 바로 ①이고 "시연 초기화" 뒤에는 다시 뜬다(움직임 줄이기 설정이면 로딩 없이 칠한 모양). 맨 위 "AI 분석 요약"이 확인할 곳 수와 먼저 볼 두 곳을 보여 준다. 인용을 누르면 공고의 그 형광펜으로 간다. 공고 원문은 실제 공고처럼 긴 글이고, 형광펜 "기타 업무 지원"을 누르면 그 줄 바로 밑에 어떤 업무 카드와 연결했는지 설명이 펼쳐진다. 오른쪽(폭이 좁으면 아래) "AI가 찾은 확인할 점"과 회사 신호의 출처 배지("실제"/"모의")를 보인다.
3. **내 기대·걱정 고르기** → ② 업무 카드 17개. 맨 위의 응용소프트웨어개발자 직무 개요 한 줄과 카드마다 붙은 "NCS" 줄은 고용24 오픈API에서 받은 실제 값이다. 카드마다 늘 있는 **도움말**을 누르면 그 업무의 예시 2개와 낯선 말 풀이가 팝업(휴대폰은 화면 아래 시트)으로 뜬다. 카드 높이는 모두 같고, 고르거나 도움말을 열어도 바뀌지 않는다. 시연 도구 → **예시 구직자 A로 채우기**(② 안의 "시연 도구 열기"로도 열린다, 직접 골라도 된다). "이력서에서 가져오기" 칩으로 경험 한 줄을 채울 수 있다.
4. **질문 만들기** → 만드는 중 3단계 → ③ **1차·기술 면접 질문** 5개. 유형 칩(차이 확인·기회 확인·깊이 확인), "왜 이 질문인가요"(근거·주의할 답·좋은 신호), **근거 보기**(① 형광펜으로 돌아감)를 보인다. 질문마다 따로 누르는 복사 버튼은 없고, 오른쪽 상자(폭이 좁거나 휴대폰이면 질문 위)의 **전체 복사**·**면접에 들고 갈 한 장 인쇄**가 화면 순서 그대로 담는다(더 알아볼 질문이 있으면 전체 복사 글 끝에 소제목 "더 알아볼 질문"과 그 문장들). 아래 고정 바에는 "면접 다녀왔어요" 하나만 있다. 1차에는 처우 질문을 주지 않는다는 점을 말한다.
5. **면접 다녀왔어요** → **1차 면접 정리**. 머리 요약에 "준비 중: 최종 면접"이 붙는다. 시연 도구 → **1차 면접 다녀온 것으로 채우기** → **최종 질문 만들기**.
6. **최종 면접·처우 질문** — 요약(확인됨 2 · 기대와 다름 1 · 아직 모름 2 · 회사가 먼저 물은 것 1)과, 확인된 것은 빼고 남은 것·처우를 묻는 질문을 보인다. 첫 질문은 1차에 가져간 질문을 이어 받아 공고 근거를 다시 묻는다. 예시 채우기가 면접 분위기를 "압박이 있었어요"로 넣으므로 첫 질문 앞에 완충 문장이 붙는다. 최종 ③에는 아래 고정 바가 없고, 오른쪽 상자의 "면접에 들고 갈 한 장 인쇄"는 A4 한 장이다.
7. (시간이 남으면) 2행 (주)△△커머스 **최종 면접 준비** — 1차 결과가 미리 들어 있는 지원 건. 주 메뉴 **채용정보** → 공고 상세 → **입사지원** → 지원 내역 맨 위에 새 행이 생기고 바로 역질문을 준비할 수 있다. ③의 **이 질문은 어떻게 만들어지나요**(`/about-ai`)는 처리 단계와 데이터 출처 표(실제/모의, 받은 날짜)를 보인다.

대체 경로를 보여 줄 때는 S4 주소 끝에 `&apiFail=1`을 붙이고(예: `…/prep?step=2&apiFail=1`) 질문을 만든다. S4 주소에는 이미 `?step=`이 있어 `?`로 붙이면 표시가 사라지고 ①로 돌아간다. "미리 검수한 문장" 안내와 함께 같은 순서의 검수 문장이 나온다(가짜 응답 모드에서만).

## 브랜치와 배포

```
staging(개발) ──push──▶ Vercel 미리보기 ──세진 확인──▶ main merge(GitHub PR) ──▶ https://askback24.vercel.app
```

- 개발은 **staging** 브랜치에서만 하고, 커밋·push도 staging에만 한다.
- **main에는 직접 커밋·push 하지 않는다.** main은 심사위원이 보는 배포 주소라, 세진이 staging 미리보기를 확인한 뒤 GitHub에서 staging → main PR로만 합친다.
- 심사 기간(11-10~19)에는 main merge를 하루 한 번 이하로, 확인한 것만 한다.
- Vercel은 `vercel.json`의 `buildCommand`대로 가짜 응답 모드(`npm run build:mock`)로 빌드한다. staging 미리보기에서 ③ 제목 옆과 `/about-ai`에 회색 태그 "가짜 응답 모드 · AI 대신 규칙과 예시 문장"이 보이는지 확인한 뒤 main에 합친다.
- 커밋 작성자는 레포 로컬 설정을 쓴다. 메시지 꼴과 그 밖의 규칙은 [`CLAUDE.md`](CLAUDE.md) 「git」을 본다.

## 제한 사항

- **모의 데이터**: 공고 7건·회사 신호 값·지원 내역·김00 이력서는 모두 예시다. 공고는 실제 공고처럼 긴 글로 썼지만 지어낸 글이고, 회사명은 가명이다. (주)◇◇데이터와 S3 추가 공고(`K-MOCK-0003`~`0007`)는 `draft: true`로, 팀 데이터가 오면 바꾼다.
- **LLM 미연결**: 실제 LLM은 연결하지 않았다(엔노이아는 이번 범위에서 뺌). AI 담당 서버를 부르는 연결 코드(`LLM_PROVIDER=remote`)와 명세는 있지만 배포는 가짜 응답 모드 그대로다(「실제 AI 연결」). 가짜 응답 모드의 질문 문장은 LLM이 아니라 규칙과 검수 틀로 만든 문장이고, 화면 제목 옆 회색 태그와 `/about-ai`에 그렇게 적혀 있다. 1차 면접 정리의 판정도 정해 둔 예시 세트(R-04)만 고정값이고, 그 밖의 입력은 단순 규칙(구체적 → 확인됨, 모호·못 물음 → 아직 모름)으로 판정한다. "기대와 다름"은 실제 LLM이 붙어야 나온다.
- **브라우저**: 화면 시험은 Chromium(데스크톱 1440, 휴대폰 375, 일부 1366×657·1152×720·960×600·390×844)만 돌았다. 3차 밤샘에 더한 화면 요소(① 로딩·형광펜, ② 도움말 팝업, ③ 오른쪽 상자, 모든 화면 안내 단계)는 375×812·390×844·1366×657·1440×900에서 가로 넘침·화면 밖 상자가 없는지 따로 확인했다(D-262). 사파리·아이폰은 사람이 직접 확인해야 한다.
- **배포**: 이 문서의 시험은 로컬 가짜 응답 모드 빌드로만 돌았다. Vercel 배포와 서버 함수(`api/questions.ts`)의 동작은 배포 쪽에서 따로 확인한다.
- **저장**: 지원 내역·선택·결과와 본 안내·본 공고 분석 로딩 기록은 이 브라우저(`localStorage`, `rq:v1:` 키)에만 저장되고 "시연 초기화"가 모두 지운다. 서버 DB가 없고, 저장이 막힌 브라우저에서는 새로고침하면 처음으로 돌아간다. 1차 면접에서 들은 답과 면접 분위기는 저장하지 않는다.
- **범위 밖**: 주 메뉴는 "채용정보"만 동작한다. 나머지 메뉴·탭·버튼은 회색 글자로 흐리게 표시했고, 누르면 "시연 범위 밖 메뉴예요" 알림만 뜬다(목록은 [`docs/DEMO-SCOPE.md`](docs/DEMO-SCOPE.md)). 직무는 백엔드 개발자만 있다.
