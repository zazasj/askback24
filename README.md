# askback24 — 면접 역질문 준비 (시연 사이트)

2026 고용24 AI 해커톤(팀 레인보우 가이즈) 2차 MVP다. 고용24 마이페이지를 닮은 **시연용 모의 화면**에 "면접 역질문 준비" 기능을 붙였다. 지원한 공고를 읽고, 구직자가 고른 기대·걱정으로 면접에서 회사에 물어볼 질문을 만든다. 1차 면접을 다녀오면 정리한 내용으로 최종 면접·처우 질문을 만든다.

> 실제 고용24가 아니다. 모든 화면 맨 위에 시연 띠가 있고, 회사·공고·인물(김00)은 모두 예시다.

문서: 계획 [`docs/PLAN.md`](docs/PLAN.md) · 완료 기준 [`docs/ACCEPTANCE.md`](docs/ACCEPTANCE.md) · 결정 [`docs/DECISIONS.md`](docs/DECISIONS.md) · 디자인 기준 [`docs/DESIGN-REVIEW.md`](docs/DESIGN-REVIEW.md) · 시험과 기준이 어긋난 것 [`docs/SPEC-ISSUES.md`](docs/SPEC-ISSUES.md)

## 실행 방법

Node 22 이상, npm을 쓴다.

```bash
npm ci
npx playwright install chromium   # 화면 시험을 돌릴 때만
```

### 시연용으로 띄우기 (가짜 응답 모드, 권장)

서버 함수 없이 브라우저 안에서 질문을 만든다. 시연과 시험은 이 모드로 한다.

```bash
npm run build:mock
npm run preview        # http://localhost:4173
```

고치면서 볼 때는 `npm run dev:mock` (터미널에 찍힌 `Local:` 주소, 보통 http://localhost:5173). Windows PowerShell 5.1은 `npm run dev -- --mode mock`의 `--`를 지워서 Vite가 `mock`을 폴더로 읽고 흰 화면(모든 주소 404)이 되므로 `dev:mock`을 쓴다.

### 실제 모드

`npm run build` / `npm run dev`는 실제 모드다. 화면이 `POST /api/questions`(Vercel 함수, `api/questions.ts`)를 부르고, 12초 안에 답이 없거나 오류가 나면 미리 검수한 문장으로 대신 보여 준다. 로컬 `npm run dev`에는 서버 함수가 없으므로 늘 검수 문장으로 대체된다.

서버 함수 환경변수는 `.env.example`을 본다. 키는 `api/` 안에서 `process.env`로만 읽고, `VITE_`로 시작하는 변수에 넣지 않는다. `.env`는 커밋하지 않는다.

| 변수 | 뜻 |
|---|---|
| `LLM_PROVIDER` | `mock`(기본) 또는 `ennoia`. 모르는 값이면 `mock` |
| `ENNOIA_API_KEY`, `ENNOIA_ENDPOINT` | 엔노이아 자리. 형식이 정해지기 전까지는 값이 있어도 부르지 않는다 |

### 시험

```bash
npm run build          # 타입 검사 + 빌드
npm run test:unit      # Vitest (shared/, api/, src/)
npm run test:e2e       # Playwright, 데스크톱 1440 · 휴대폰 375 (Chromium)
npm run test:e2e -- --grep "S4-13"   # 특정 ID만
npm run screens        # 화면 캡처 → review/screens/*.png
npm run check          # 위 세 가지(build · test:unit · test:e2e)를 차례로
```

화면 시험은 `vite build --mode mock` + `vite preview`(포트 4173)를 스스로 띄운다. 4173 포트가 비어 있어야 한다.

## 시연 순서 (3~5분)

시작 전에 맨 위 시연 띠 오른쪽 끝의 **시연 도구 → 시연 초기화**를 누르면 지원 내역·선택·결과·안내 띠가 처음으로 돌아간다.

1. **알선/입사지원 내역** (`/mypage/applications`) — 고용24 표에 "면접 준비" 열(AI 라벨, 보라색)만 새로 붙였다는 점을 보인다. 안내 띠가 첫 행 버튼을 가리킨다.
2. 1행 (주)OO소프트 **면접 역질문 준비** → ① **공고 확인**. 공고 원문의 형광펜 "기타 업무 지원"을 누르면 어떤 업무 카드와 연결했는지 설명이 뜬다. 오른쪽(폭이 좁으면 아래) "AI가 찾은 확인할 점"과 회사 신호의 출처 배지("실제"/"모의")를 보인다.
3. **내 기대·걱정 고르기** → ② 업무 카드 17개. 시연 도구 → **예시 구직자 A로 채우기**(직접 골라도 된다). "이력서에서 가져오기" 칩으로 경험 한 줄을 채울 수 있다.
4. **질문 만들기** → 만드는 중 3단계 → ③ **1차·기술 면접 질문** 5개. 유형 칩(충돌 확인·기회 확인·깊이 확인), "왜 이 질문인가요"(근거·주의할 답·좋은 신호), **근거 보기**(① 형광펜으로 돌아감), 복사·전체 복사·인쇄를 보인다. 1차에는 처우 질문을 주지 않는다는 점을 말한다.
5. **면접 다녀왔어요** → **1차 면접 정리**. 시연 도구 → **1차 면접 다녀온 것으로 채우기** → **최종 질문 만들기**.
6. **최종 면접·처우 질문** — 요약(확인됨 2 · 기대와 다름 1 · 아직 모름 2 · 회사가 먼저 물은 것 1)과, 확인된 것은 빼고 남은 것·처우를 묻는 질문을 보인다. 예시 채우기가 면접 분위기를 "압박이 있었어요"로 넣으므로 첫 질문 앞에 완충 문장이 붙는다.
7. (시간이 남으면) 2행 (주)△△커머스 **최종 면접 준비** — 1차 결과가 미리 들어 있는 지원 건. 주 메뉴 **채용정보** → 공고 상세 → **입사지원** → 지원 내역 맨 위에 새 행이 생기고 바로 역질문을 준비할 수 있다. ③의 **이 질문은 어떻게 만들어지나요**(`/about-ai`)는 처리 단계와 데이터 출처를 보인다.

대체 경로를 보여 줄 때는 S4 주소 끝에 `?apiFail=1`을 붙이고 질문을 만든다. "미리 검수한 문장" 안내와 함께 같은 순서의 검수 문장이 나온다(가짜 응답 모드에서만).

## 제한 사항

- **모의 데이터**: 공고 7건·회사 신호·지원 내역·김00 이력서는 모두 예시다. S3 추가 공고 4건(`K-MOCK-0004`~`0007`)과 (주)◇◇데이터 공고는 `draft: true`로, 팀 데이터가 오면 바꾼다. "실제" 배지가 붙은 신호도 출처 종류만 실제이고 값은 예시다.
- **LLM 미연결**: 실제 LLM(엔노이아)은 연결하지 않았다. 가짜 응답 모드의 질문 문장은 LLM이 아니라 규칙과 검수 틀로 만든 문장이다. 1차 면접 정리의 판정도 정해 둔 예시 세트(R-04)만 고정값이고, 그 밖의 입력은 단순 규칙(구체적 → 확인됨, 모호·못 물음 → 아직 모름)으로 판정한다. "기대와 다름"은 실제 LLM이 붙어야 나온다.
- **사파리 미시험**: 화면 시험은 Chromium(데스크톱 1440, 휴대폰 375)만 돌았다. 사파리·아이폰은 사람이 직접 확인해야 한다.
- **배포 미확인**: Vercel 배포와 서버 함수(`api/questions.ts`)의 실제 동작은 확인하지 않았다(D-015, D-018).
- **저장**: 지원 내역·선택·결과는 이 브라우저(`localStorage`, `rq:v1:` 키)에만 저장된다. 서버 DB가 없고, 저장이 막힌 브라우저에서는 새로고침하면 처음으로 돌아간다. 1차 면접에서 들은 답과 면접 분위기는 저장하지 않는다.
- **범위 밖**: 주 메뉴는 "채용정보"만 동작하고, 나머지 메뉴와 왼쪽 메뉴의 다른 묶음은 "시연 범위 밖 메뉴예요" 알림만 띄운다. 직무는 백엔드 개발자만 있다.

## 폴더

```
api/        Vercel 함수 (요청 검사 → shared/generate → 응답). 키는 여기서만 읽는다
shared/     화면과 서버가 같이 쓰는 규칙·검사·생성·공급자(mock, ennoia 자리)
data/       업무 카드, 모의 공고·분석, 회사 신호, 김00 이력서, 지원 내역 시드, 예시 구직자
src/        화면 (Vue 3 + Vite + TypeScript, Pinia, KRDS 토큰·글꼴)
e2e/        Playwright 시험 (시험 작성자 소유, 개발 중 고치지 않음)
docs/       계획·완료 기준·결정·디자인 기준
```
