# 개발 5단계 계획 — ④ 평가와 ② 질문 맞춤화

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 로컬 평가(`evals/`)로 ⓪①②③의 답 품질을 재고, ② 1차 질문에 공고 내용과 이력서를 넣어 그 전후를 같은 자료로 비교한다.

**Architecture:**
- 평가는 API 계약(요청 → 응답)만 본다. 그래프 안쪽은 보지 않는다.
- **①**: Python이 `AnalysisAgent`를 프로세스 안에서 부른다.
- **②③**: TS 스크립트가 `shared/` 규칙 → 로컬에 띄운 Python AI 서버 → TS 최종 검사까지 실제 경로 그대로 돌린다. 서버는 스크립트가 띄우고 끈다.
- 판정 LLM 지표와 요약은 Python이 실행 폴더(`review/evals/<실행>/`)의 결과 파일을 읽어 낸다.
- ② 맞춤화는 프롬프트, 실행 중 검사(기술 낱말), 요청 계약(이력서 허용 목록)을 바꾼다.

**Tech Stack:** Python 3.12 · uv · pytest · LangGraph(기존 그래프) · TypeScript · Vitest · Vite `runnerImport`(기존 `api:examples` 꼴) · Node `child_process`

**Spec:** `docs/ai_agent/개발 5단계 설계.md`(이 계획의 근거) · `docs/ai_agent/에이전트 설계 확정.md` §1·§3·§5 · `docs/AI-API-명세서.md` 1~3번 · D-306·D-313·D-344

**범위 밖:**
- 공고 30건 고르기와 정답표 매기기(사람 일, 설계 §8-1)
- 고용24 채용정보를 받아오는 스크립트(사람이 공고 JSON을 붙여 넣는다)
- 가짜 응답 모드(`build:mock`)의 이력서 사용
- ③ `final-questions`에 이력서 보내기
- ⓪ 프롬프트 고치기(평가만)

## Global Constraints

**키와 실제 공고**
- 키는 `os.environ`/`process.env`로만 읽는다. 키·공고 원문·질문 원문·경험·이력서를 콘솔·로그에 찍지 않는다. 콘솔에는 건수와 지표만 찍는다.
- 실제 공고, 정답표, 사람 점수는 `evals/data/`에만 둔다. 실행 결과는 `review/evals/`에만 둔다. 둘 다 git 밖이다. 커밋하는 평가 자료는 가상 인물(`evals/personas/`)과 빈 양식(`evals/templates/`)뿐이다.

**코드 규칙**
- `api/`·`shared/` 안에서는 상대경로로 import 한다. `evals/`는 `api._agent.*`로 import 한다(`regen.py`와 같은 꼴). `_agent.*`로 import 하지 않는다.
- 실행 중 검사 규칙을 바꿀 때는 `shared/fixtures/validate-cases.json`에 예시를 먼저 더한다. 그다음 TS `validate.ts`와 Python `checks.py`가 같은 결과를 내게 한다.
- 시간 예산은 그대로다: ② 18초 · ③-1 8초 · ③-2 10초 · TS가 기다리는 시간 20초(`PROVIDER_TIMEOUT_MS`).
- 판정 LLM은 기존 `llm()`의 `"accurate"` 역할로 부른다. DeepEval은 쓰지 않는다.
- 이력서 허용 목록: `career`(희망 경력 구분) · `skills` · `projects[].{name,stack,summary}` · `trainings[].{name,summary}` · `certificates[]`(이름만). 이 밖의 칸은 AI로 가지 않는다.
- 화면 문구(`/about-ai` 개인정보, `ACCEPTANCE.md` 「정확한 문구」)는 세진이 승인한 뒤에만 바꾼다.

**작업 규칙**
- `e2e/`·CLAUDE.md는 고치지 않는다. 서버를 백그라운드로 남기지 않는다.
- 커밋 메시지는 `[Feat] 5단계 …` / `[Fix] …` / `[Docs] …` 꼴이고, 끝에 빈 줄 + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`을 붙인다. 바꾼 경로만 적어 add 한다. push 하지 않는다.
- DECISIONS에는 한 줄씩, 다음 빈 번호부터 적는다.

## Review Focus

1. **엑셀에서 내려받은 CSV(UTF-8 BOM, CRLF, 끝 빈 줄)** → 그대로 읽혀야 한다. 시험: Task 2 `test_reads_excel_csv`.
2. **판정 LLM이 JSON이 아니거나 범위 밖 번호로 답함** → 맞음·틀림이 아니라 "판정 실패"로 따로 센다. 지표 분모에서도 뺀다. 시험: Task 4 `test_bad_choice_is_none`, Task 8 `test_failed_judges_excluded`.
3. **평가 스크립트가 중간에 터짐** → 띄운 Python 서버는 반드시 꺼진다. 시험: Task 6 `withServer kills on throw`.
4. **기술 낱말의 표기 차이와 오탐**
   - 같은 낱말로 봐야 하는 것: 스프링/Spring, 대소문자, 띄어쓰기
   - 걸리면 안 되는 것: 다른 영어 낱말 안의 짧은 낱말(예: `SM`이 `SMS` 안에서 걸림)
   - 시험: Task 7 픽스처 사례
5. **이력서에 허용 목록 밖 칸(이름·연락처·병역·자기소개)이 섞여 옴** → 요청에서 빠진다. 화면이 보내도, TS 서버가 받아도 같다. 시험: Task 11 `cleanResume drops unknown fields`.

### Task 4: 판정 LLM

**Files:**
- Create: `evals/judges.py`, `evals/tests/test_judges.py`

**Interfaces:**
- Consumes: `api._agent.llm.Llm`·`LlmError`·`FakeLlm`(시험)
- Produces(모두 `role="accurate"`, `timeout_s=60`. LLM 오류·JSON 아님·범위 밖이면 `None`):
  - `async def guess_posting(llm, question: str, options: list[dict], rng: random.Random) -> int | None`
