# 개발 3단계 계획 — ① 공고 분석 · 회사 확인 · 회사 신호

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Python AI 서버에 ① `POST /api/ai/v1/posting-analysis`를 연다. 공고 한 건을 받아 카드 상태·근거·이유, 처우 빈칸, 회사 신호(신호 질문 포함)를 돌려준다. 이 결과로 시연 공고 7건의 `data/analysis/*.json`·`data/signals.json`을 다시 만들 후보와 비교 보고서를 낸다.

**Architecture:**
- 그래프는 §9-4대로 네 갈래가 나란히 돈다.
  - 카드 판정: 독립 2회 + 걸린 카드만 1회 다시
  - 처우 빈칸: 코드
  - 회사 자료 조회: 실제 API + 파일
  - 신호 질문: LLM + 규칙 검사
- 갈래 결과는 `merge`에서 모은다.
- 회사는 `REAL_COMPANY_MAP` → 공고 `bizNo` → 시연 모의 값(`data/company/demo.json`) 순서로 찾는다. 실제 이름·사업자번호는 그래프 상태 안에만 있다.
- 외부 자료는 셋이다. 국민연금은 실시간 data.go.kr, 강소기업은 매핑 공고만 스크립트로 뽑은 파일, EIS 업종 기준값은 스크립트로 만든 파일이다.
- 다시 만든 결과를 커밋 파일에 바로 쓰지 않는다. 후보와 비교 보고서를 만들고, 사람이 보고 적용한다. 시연 7건 값은 e2e·단위 시험이 직접 읽기 때문이다.

**Tech Stack:** Python 3.12 · uv · FastAPI · LangGraph · httpx · pydantic 2 · pytest / TS 스크립트 · Vitest

**Spec:** `docs/ai_agent/에이전트 설계 확정.md` §2 ①·「회사 신호를 켜는 규칙」·「회사 확인과 실제 데이터」, §3, §6, §9-4 · 호출 형식 `docs/AI-API-명세서.md` 3번 · `docs/LATER.md` 1번·4번 · 1·2단계 계획

## Global Constraints

- 1·2단계 Global Constraints를 그대로 따른다.
  - 키는 `os.environ`으로만 읽는다.
  - 로그에 글을 남기지 않는다.
  - `e2e/`는 고치지 않는다. 깨지면 SPEC-ISSUES에 적는다.
  - 커밋 형식과 Co-Authored-By를 지킨다. 경로를 적어 add 한다. push 하지 않는다.
  - 결정은 `docs/DECISIONS.md`에 한 줄씩 적는다(D-344부터).
- **실제 회사 이름·사업자번호·주소**는 응답·로그·오류·`data/`·`review/`·시험 파일 어디에도 쓰지 않는다. 시험의 "실제" 회사는 `(주)테스트실제`·`000-00-00000` 같은 가짜 값만 쓴다.
- 저장·화면 문장은 구간·방향만 쓴다. 가입자 수 구간 `MEMBER_BANDS = [(1, 9, "1~9명"), (10, 29, "10~29명"), (30, 99, "30~99명"), (100, 299, "100~299명"), (300, None, "300명 이상")]`.
- 매핑으로 받은 신호는 `source: "실제"`이고 `caveat`에 `"실제 공공데이터 값을 시연용 가상 회사에 붙여 보여 줘요"`를 넣는다. 모의 값이면 `source: "모의"`이다. EIS 기준값은 회사와 상관없는 값이라 늘 `"실제"`이다.
- 외부 API가 실패하거나 늦거나 0건·여러 건이면 **그 신호만 뺀다**. 분석은 계속한다.
- 단위 시험·빌드·pytest는 실제 API를 부르지 않는다. httpx는 `MockTransport`로 가짜 응답을 준다. 실제 호출 시험은 키가 있을 때만 돈다(`test_*_live.py`, 1단계 `test_llm_live`와 같은 꼴).
- 시간:
  - 엔드포인트 전체 `ANALYSIS_DEADLINE_S = 50.0`(Vercel `maxDuration` 60 안)
  - LLM 한 번은 `min(25.0, 남은 시간)`
  - 다시 판정은 남은 시간이 `RECLASSIFY_MIN_LEFT_S = 15.0` 이상일 때만
  - 신호 질문은 남은 시간이 `SIGNAL_ASK_MIN_LEFT_S = 8.0` 이상일 때만 한다. 모자라면 검수 질문을 쓴다.
  - 국민연금 전체 `NPS_BUDGET_S = 20.0`, 호출 한 번 `NPS_CALL_TIMEOUT_S = 5.0`, 동시 4개
- LLM 역할: 카드 판정과 다시 판정은 `"accurate"`, 신호 질문은 `"fast"`(§4).
- 로그 한 줄. 글·회사 정보 없이 출처별 성공 여부만 남긴다.
  - 성공: `[ai] analysis job=backend cards=17 needs_review=2 retried=a,b signals=reposting,pension_flow sources=nps:ok,eis:none,giants:mock ms=… model=…`
  - 503: `[ai] analysis unavailable code=… ms=…`
