6. 구현 중 내린 판단

계획에 없던 것을 정한 것입니다. 틀렸다면 무엇을 되돌리면 되는지 함께 적었습니다.

단계판단틀렸을 때
1단계Python 로거를 앱에서 직접 설정하고, 다시 쓰기에 고칠 점 힌트를 붙임(최종 검토 반영)설정 한 곳만 되돌림
2단계TS 판정 수용 조건을 동작 그대로 judgementIssues 함수로 뽑음함수 하나 되돌림
2단계③-2 예산은 바꾸지 않고 다시 쓰기가 거의 안 도는 사실을 기록(D-343)걸린 문항이 검수 문장으로 나감(완충 포함)
3단계시연 모의 연금 값은 12개월 요약으로 보고 같은 모양(PensionFacts)으로 씀어댑터 한 곳 수정
3단계EIS 규모 구간은 스크립트 한 곳에 두고 파일 meta로 Python에 넘김, 실제 파일 전까지 임시 이름파일 받을 때 이름만 고침
3단계임금체불 신호는 명단에 있을 때만, "명단에 없음" 줄은 사람 글로 남김필요하면 종류 하나 더함
3단계국민연금 신호는 퇴사 > 입사 한 문장만, 출처별 배지 · 주의 문구 구분없음
3단계신호 질문 전용 금지 표현 목록은 Python에만 둠(TS 공유 목록은 그대로)없음
3단계실제 회사인데 국민연금이 실패하면 모의 숫자로 채우지 않고 그 신호를 뺌매핑 공고에 연금 줄이 안 보임
3단계§9-4 합류를 다시 판정이 끝난 뒤(settled_a/b)로 옮김합류 노드 두 개 되돌림
3단계서브에이전트가 적은 커밋 끝 줄을 CLAUDE.md 형식으로 고침(push 전, 코드 같음)없음
3단계다시 만들기 보고서가 남긴 옛 "실제" 줄을 따로 보이는 일은 4.5단계 첫 적용 전으로 미룸보강 없이 적용하면 잘못된 배지가 남을 수 있음(4.5 체크 목록에 있음)
4.5단계3·4단계는 실제 API 코드 + 가짜 응답 시험, 실행은 모의 · 스냅숏, 전환은 평가 전(D-344, 사용자 결정)—
4단계meta.sources에는 실제로 부른 출처만 적음없음
4단계직무정보 추천은 후보 능력단위 이름(띄어쓰기 뺌)으로 20번까지만 부름교차 세분류 추천이 적을 수 있음
4단계CLI는 LLM 한 번 상한도 마감에 맞춰 늘리고, 자료 받기도 마감 안에서없음
4단계엔드포인트는 지금 모델로 시간 초과될 수 있어 CLI를 공식 경로로 문서화(4.5에서 결정)엔드포인트를 쓰려면 상한 · 모델 조정
