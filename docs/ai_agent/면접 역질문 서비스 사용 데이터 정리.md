# 면접 역질문 서비스 사용 데이터 정리

> 데이터를 에이전트가 어떻게 쓰는지(회사 신호를 켜는 규칙, EIS 업종 기준값 등)는 [에이전트 설계 확정](./에이전트%20설계%20확정.md)을 따라요.

기획서의 '데이터 활용 명세'를 기준으로, 2026-10-25에 직접 신청·확인한 결과를 반영했어요. 원칙은 **공개된 공공데이터는 실제로 쓰고, 개인이 받을 수 없는 채용정보 API와 구직자 정보만 모의 데이터로 만든다**예요.

## 데이터 목록

| 데이터 | 출처 | 명세 구분 | 현재 상태 | 주요 항목 | 활용 단계 |
| --- | --- | --- | --- | --- | --- |
| 채용공고 목록·상세 | 고용24 API 명세 기반 생성 + 공개 화면 일부 | 모의 | 모의 확정 (개인회원은 채용정보 목록·상세 API 이용 불가) | 직무내용, 우대사항, 근로조건, 업종코드, 근로자 수 | 공고 분석 |
| 표준직무기술서·직무데이터사전 | 고용24 OpenAPI (직무정보) | 실제 | ✅ 인증키 발급, 응답에 `ablt_unit`(NCS 능력단위 코드) 확인 | NCS 능력단위, 수행직무 | 업무 카드 |
| 한국직업사전 | 고용24 OpenAPI (직업정보) | 실제 | ✅ 인증키 발급 | 직업별 수행직무 | 업무 카드 문구 |
| 청년친화강소기업 | 고용24 OpenAPI | 실제 | ✅ 인증키 발급 | 기업명, 사업자등록번호, 선정연도 | 참고 신호 |
| 임금체불 명단공개 사업주 | 고용24 OpenAPI | 실제 | ⚠️ 회사 단위 데이터 없음 (지역·연도별 집계 파일만 있음) → 모의로 변경 예정 | 명단 공개 여부 | 처우 질문 순서 |
| 공고 등록 이력 | 고용24 공개 화면 | 실제 | ⚠️ 공개 화면 수집 허용 여부 문의 필요, 불가하면 모의 | 같은 직무 재등록 횟수 | 참고 신호 |
| 국민연금 가입 사업장 내역 | 국민연금공단 · data.go.kr | 실제 | 활용신청 필요 (자동 승인) | 월별 가입자·취득·상실, 업종 | 인원 흐름 신호 |
| 고용보험 피보험자 현황 | 한국고용정보원 EIS (파일) | 실제 | 파일 다운로드 가능 확인 | 피보험자수(전체), 취득자수(월), 상실자수(월) | 업종 평균 비교 ('추정') |
| NCS 분류 (능력단위명) | 한국산업인력공단 · data.go.kr (CSV 또는 국가직무능력표준 정보 API) | 명세에 없음 | `ablt_unit` 응답에 능력단위명이 없을 때만 추가 | 능력단위 코드 → 이름 | 업무 카드 표시 |
| 구직자 선택·경험 한 줄 | 시연용 생성 | 모의 | 모의 | 업무 카드 선호, 경험 | 질문 정렬 |

- 문제 정의에 쓴 청년층 부가조사(MDIS)는 서비스 안에서는 쓰지 않아요.
- 공채속보·공채기업정보 API는 대기업 공채 위주라 중소 IT 기업 공고와 맞지 않아 쓰지 않아요.

## 파이프라인과 연결

- **공고 분석 파이프라인(정적)**: 채용공고, 표준직무기술서(`ablt_unit`), 한국직업사전, NCS 능력단위명을 사용해요. 카드별 공고 상태와 근거 문장을 만들어요.
- **회사 신호 조회(코드, LLM 없음)**: 국민연금, 고용보험 EIS, 청년친화강소기업, 임금체불 명단, 공고 등록 이력을 사용해요. 숫자는 조회한 값만 써요.
- **1차·최종 질문 파이프라인(동적)**: 구직자 선택·경험, 저장된 분석 결과, (최종 면접은) 사용자가 입력한 면접 후기를 사용해요.

## 업무 카드 정의 (백엔드 개발자 17개)

- 15개는 NCS 능력단위와 연결돼요(응용SW엔지니어링 · DB엔지니어링 · IT시스템관리). 예: 신규 API 개발 = 서버프로그램 구현, 기존 시스템 유지보수 = 응용SW 운영관리.
- 연결은 **카드 ID → `ablt_unit` 목록** 표 하나로 관리해요. 코드 뒤에 버전(예: `_23v6`)이 붙으면, 비교할 때 버전을 뗄지 정해요.
- 2개(고객사 상주 개발, 혼자 맡는 백엔드)는 NCS에 없는 근무 방식이에요. 공고 문구, 팀 규모, 공고 반복 등록으로 찾아내요.

## 공고 상태 정의

- **직접 적힘**: 공고에 그 업무가 명시되어 있음
- **유추됨**: 직접 적혀 있지는 않지만 문맥상 포함된다고 판단됨
- **모호함**: '기타 업무 지원'처럼 범위가 불분명함
- **없음**: 공고에 관련 내용이 없음

## 회사 연결과 한계

- 기획서 기준: 공고 50건의 회사 41곳 중 38곳(93%)을 국민연금 사업장과 연결했고, 사업자번호가 보이는 32곳 중 28곳(88%)은 번호 앞자리까지 맞았어요.
- 국민연금은 3인 이상 법인과 10인 이상 개인사업장만 들어 있어요. 조회되지 않는 것을 나쁜 신호처럼 보여주지 않아요.
- 연결되지 않은 회사는 고용보험 EIS의 같은 업종·규모·지역 평균을 '추정'으로 표시해요.
- 청년친화강소기업은 사업자등록번호로 국민연금과 같은 회사인지 맞춰요. 화면에는 "○○년 선정"처럼 선정연도를 함께 보여줘요.

## 고용보험 EIS 파일 설계

업종·규모·지역·기간을 **모두 행**으로, 측정값 3개만 열로 받아요(긴 형식). 회사 조건 하나로 한 줄을 바로 찾기 위해서예요.

| 기준년월 | 업종코드 | 업종명 | 규모 | 시도 | 피보험자수 | 취득자수 | 상실자수 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 2026-08 | 62 | 컴퓨터 프로그래밍, 시스템 통합 및 관리업 | 30\~99인 | 서울 | … | … | … |

- **업종**: 산업분류 중분류(2자리). 주로 58(출판업, 소프트웨어 개발 포함), 62, 63이 쓰여요.
- **규모**: EIS 구분을 그대로 쓰고, 공고 근로자 수나 국민연금 가입자 수를 구간에 넣는 함수를 만들어요.
- **지역**: 시도(17개).
- **기간**: 최근 24개월, 월별.
- **보조 파일**: 업종 × 규모 × 월(전국). 해당 칸의 피보험자가 기준(예: 1,000명)보다 적으면 전국 값을 쓰고 "전국 평균"으로 표시해요.
- **코드에서 계산**: 월 상실률(상실 ÷ 피보험자), 순증(취득 − 상실). 국민연금과 집계 기준이 달라서 "높다/낮다"고 판정하지 않고 참고값으로만 보여줘요.

## 모의 데이터 생성 방법

원칙은 **실제 API 응답과 같은 필드 이름·구조로 만든다**예요.

| 데이터 | 만드는 방법 | 규모 |
| --- | --- | --- |
| 채용공고 | 고용24 채용정보 API 명세의 응답 필드 이름을 그대로 써요. 모호한 표현·근무시간 미기재처럼 확인할 점이 있는 공고를 일부러 섞고, EIS 행을 찾을 수 있게 **업종코드와 근로자 수** 필드를 꼭 넣어요. | 점검용 30건 + 시연용 3건 |
| 임금체불 명단 여부 | 사업자번호 → Y/N. 시연 회사 중 1곳만 Y로 두고, 화면에 '시연용 값'이라고 표시해요. | 시연 회사 수만큼 |
| 공고 등록 이력 (수집 불가 시) | 모의 공고의 등록일자로 계산해요. 시연 회사 하나는 6개월 안에 3번 등록되게 만들어요. | 시연 회사 수만큼 |
| 구직자 선택·경험 | 예시 구직자 2\~3명을 JSON으로 만들어요(카드 선택 + 경험 한 줄). | 2\~3명 |

- 회사명은 (주)OO소프트처럼, 사업자번호는 존재하지 않는 형식으로 만들어 실제 회사와 겹치지 않게 해요.
- 화면에서 채용공고에는 "고용24 채용정보 API 명세와 같은 구조의 시연용 공고"라고 표시해요.

## 운영 원칙

- 인증키는 소스코드·화면·공개 저장소에 넣지 않고 Vercel 환경변수로 관리해요.
- 개발계정 트래픽 한도가 있으니, 공고 분석 단계에서 한 번 조회한 결과를 저장해 써요.
- 이용허락범위는 모두 제한 없음이지만, 화면의 데이터 출처 영역에 출처를 표시해요.
- 구직자의 선택과 경험은 브라우저에만 저장하고 회사로 보내지 않아요.
- 모의 데이터는 실제 데이터를 받은 뒤에도 장애 대비용으로 남겨 둬요.

## 운영사무국 문의 초안

> 안녕하세요, ○○팀입니다. 1차 제출한 데이터 활용 명세 관련해 두 가지 문의드립니다.
>
> 1. 고용24 채용정보 API를 개인회원이 쓸 수 없어, 공고 문구와 공고 등록 이력을 고용24 공개 화면에서 참고하려 합니다. 공개 화면의 내용을 수집하거나 옮겨 쓰는 것이 허용되는지 궁금합니다.
> 2. 확인 결과 임금체불 명단은 회사 단위 데이터를 확보하기 어려워, 구분을 실제에서 모의로 바꿀 예정입니다. 명세를 다시 제출해야 하는지, 최종 제출 때 반영하면 되는지 안내 부탁드립니다.

## API 활용 목적 문구

> 고용24 주관 'AI를 접목한 고용24 서비스' 해커톤 출품작 개발에 활용합니다. 구직자가 면접에서 회사에 물어볼 질문을 준비하도록 돕는 비영리 서비스로, 채용공고를 NCS 능력단위·표준직무기술서와 비교해 확인이 필요한 업무를 찾고, 국민연금 가입 사업장 정보로 회사의 인원 변동을 참고 신호로 보여줍니다. 조회 결과는 질문 생성의 근거로만 쓰고, 개인정보는 수집하지 않으며, 화면에 데이터 출처를 표시합니다.
