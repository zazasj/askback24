# 개발 2단계 계획 — ③ 최종 면접 판정·질문

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Python AI 서버에 ③-1 `POST /api/ai/v1/final-judgements`(1차 면접 답 판정)와 ③-2 `POST /api/ai/v1/final-questions`(최종 면접·처우 질문 문장)를 열어, 지금 404라 늘 단순 규칙·검수 문장으로 대신하던 최종 면접 흐름을 엔노이아로 돌린다.

**Architecture:** TS 쪽(`shared/generate.ts generateFinal`)은 이미 판정 → 순서 규칙(`finalRules.ts`) → 문장 → 검사 순서로 두 주소를 부르고, 실패하면 단순 규칙 판정·검수 문장으로 대신한다. 이 계획은 TS를 바꾸지 않고 Python 쪽만 만든다.
- 1단계의 쓰기 → 검사 → 다시 쓰기 그래프를 공통 틀로 뽑는다. ②와 ③-2가 같은 틀을 쓰고, 앱이 뜰 때 한 번만 compile한다.
- ③-1은 다시 판정하지 않는 짧은 그래프다.
- 검사는 1단계처럼 TS `validate.ts`·`generate.ts mergeJudgements`와 같은 규칙을 같은 예시 파일로 맞춘다.

**Tech Stack:** Python 3.12 · uv · FastAPI · LangGraph · pydantic 2 · pytest / 기존 TS · Vitest

**Spec:** `docs/ai_agent/에이전트 설계 확정.md` §2 ③, §3, §5, §9-2, §9-3 · 호출 형식 `docs/AI-API-명세서.md` 2번(2-1·2-2)과 「응답 규칙」 · 1단계 결과 `docs/ai_agent/개발 1단계 계획.md`

**범위 밖:** TS 코드 변경, ① 공고 분석, ⓪ 카드 초안, ④ 평가, 시연 프리셋 캐시, `docs/API-SPEC.md` 시간 문구(SPEC-ISSUES AS-05 대기).

## Global Constraints

- 1단계 Global Constraints를 그대로 따른다(키는 `os.environ`만, 로그에 글 없음, `e2e/` 수정 금지, 커밋 형식·Co-Authored-By, 경로를 적어 add, push 안 함, 결정은 `docs/DECISIONS.md`에 한 줄씩).
- **들은 답(`heard`)은 판정 호출에만 쓴다.** 로그·오류·응답 어디에도 남기지 않고, 문장 호출(`final-questions`)에는 처음부터 없다.
- 예산: ③-1 `JUDGE_BUDGET_S = 8.0`(다시 판정 없음), ③-2 `FINAL_BUDGET_S = 10.0`(다시 쓰기 문턱 `RETRY_MIN_LEFT_S = 8.0`, 여유 `REWRITE_SAFETY_S = 1.5`는 1단계 값 그대로). TS는 두 호출이 20초 하나를 나눠 쓴다.
- 판정 수용 규칙(TS `mergeJudgements`와 같음): `state`는 `confirmed`·`mismatch`·`still_unknown` 중 하나이고, `basis`는 공백을 한 칸으로 줄인 뒤 1~160자(`JUDGE_BASIS_MAX = 160`)여야 한다. 6자 이상인 들은 답(`HEARD_QUOTE_MIN = 6`)을 그대로 옮기면 안 되고, 금지어가 있어도 안 된다.
- 최종 문장 검사(TS `checkFinalQuestion`과 같음): 공통 검사(빈 문장·길이·인용·금지어) + `absent` 전제 + 1차 면접관 말 `INTERVIEWER_QUOTE = /아까|하셨는데|말씀하신/`. 들은 답 대조는 Python에서 할 수 없다(요청에 없음). 이 부분은 TS가 마지막에 본다.
- **Python만 보는 검사 `cushion_missing`**: `tone`이 `cushion`인데 문장이 `cushion` 문장(앞뒤 공백 제거)으로 시작하지 않으면 다시 쓴다. TS는 이 검사를 하지 않고 명세가 AI에게 맡긴 규칙이라, 예시 파일에는 넣지 않고 pytest로만 본다.
- 오류: 첫 LLM 호출이 `LlmError`면 503 `unavailable`이다. 응답에는 통과한 것만 요청 순서대로 담는다. 빠진 문항·판정은 TS가 검수 문장·단순 규칙으로 채운다.
- 로그 한 줄(글 없음):
  - `[ai] judge n=4 passed=3 card_id=BE15,BE07,BE02,BE01 issues=BE02:basis_heard ms=… model=…`
  - `[ai] final n=7 passed=6 retried=1 key=BE15,BE08,…,offer:sal issues=offer:sal:too_long ms=… model=…`
  - 503일 때: `[ai] judge unavailable code=… ms=…` · `[ai] final unavailable code=… ms=…`

## Review Focus

1. 같은 카드를 두 번 판정하거나 요청에 없는 카드를 판정해도, 요청 카드만 처음 것으로 받는다 — Task 3 `test_judge_pairs_by_card_id`.
2. 판정 근거가 들은 답을 6자 이상 그대로 옮기면 그 판정만 빠진다(TS도 받지 않는 것을 앞에서 거름) — Task 2 예시 `"들은 답 옮김"`, Task 3 `test_judge_drops_basis_quoting_heard`.
3. `cushion` 문항에서 완충 문장이 빠지거나 바뀌면 그 문항만 다시 쓰고, 그래도 빠지면 문항이 빠져 TS 검수 문장(완충 포함)이 나간다 — Task 4 `test_final_rewrites_missing_cushion`.
4. 처우 질문(`key: "offer:sal"`, `card_id` 없음)이 카드 질문과 섞여도 `key`로 짝짓는다 — Task 4 `test_final_pairs_by_key_with_offer_items`.
5. 들은 답이 로그·오류에 새지 않는다(판정 400·503·성공 모두) — Task 3 `test_judge_never_logs_heard`.
