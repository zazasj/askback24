## 공통

- 브랜치는 **staging**이다. main은 건드리지 않는다. 커밋은 마일스톤마다 하고 push는 릴리스 단계에서 한 번만 한다.
- 고용24 API는 `scripts/fetch-work24.ts`만 부른다. 다른 코드·시험·빌드는 API를 부르지 않는다. 키는 `.env`(`WORK24_KEY_*`)에서만 읽고, 출력·로그·커밋에 키를 남기지 않는다.
- 호출 주소 앞부분: `https://www.work24.go.kr/cm/openApi/call/wk/`. 10-25 실측:
  - 직무정보 `callOpenApiSvcInfo215L01.do?authKey=…&returnType=JSON&jobCont=<업무 설명>&limit=<n>` → `result` 아래 능력단위별 `ablt_def`·`job_sdvn`·`job_scfn` 등
  - 직업정보 `callOpenApiSvcInfo212L01.do?authKey=…&returnType=XML&target=JOBCD&srchType=K&keyword=웹` → 목록, `callOpenApiSvcInfo212D01.do?authKey=…&returnType=XML&target=JOBDTL&jobGb=1&jobCd=K000001106&dtlGb=1` → 직무 개요(`jobSum`) 등
  - 공통코드 `callOpenApiSvcInfo21L01.do?authKey=…&returnType=XML&target=CMCD&dtlGb=1` → 지역코드(다른 `dtlGb` 값은 응답을 보고 판단)
  - 강소기업 `callOpenApiSvcInfo216L01.do?authKey=…&callTp=L&returnType=XML&startPage=1&display=<n>` → `smallGiantsList`(`total` 15,291 · `sgBrandNm` · `superIndTpNm` 등)
  - 채용정보 `210L01`은 "개인회원은 사용할 수 없는 OPEN-API" — 부르지 않는다.
- 호출 한도: 1초에 1번 이하, 한 번 실행에 200번 이하. `.cache/work24/`에 원본을 두고, 있으면 다시 부르지 않는다. 오류 응답(`<error>`)이면 멈추고 보고한다.

## N2 공공데이터 연결 (DATA-01~07)

- `scripts/fetch-work24.ts` + `package.json` `fetch:work24`(`node --env-file=.env` 또는 dotenv 없이 Node 22 기능으로 키 읽기).
- 직무정보: 카드 17개 중 NCS 연결 15개의 설명 문장으로 하나씩 부르고(15번), 응답 상위 결과 중 기존 NCS 능력단위명과 같거나 가장 가까운 것을 고른다. 고른 근거(응답 순위·이름)를 `ncs-cards.json`에 같이 적는다. 맞는 것이 없으면 `matched: false`.
- 직업정보: 웹개발자 상세 1번(필요하면 dtlGb 몇 가지). 직무 개요 한두 문장을 ② 위에 출처와 함께.
- 공통코드: 지역코드 1번(+직종코드). 모의 공고 7건의 지역·직종 코드를 실제 코드로 맞춘다.
- 강소기업: 전체 수는 첫 호출의 `total`로 센다. 업종·인증 종류 통계는 `display`를 크게(응답이 허용하는 만큼) 해서 최대 160번 안에서 센다. 다 못 세면 센 범위를 파일에 적는다(지어내지 않음). 회사명·사업자번호는 `.cache/`에만 남긴다.
- /about-ai 출처 표와 문구를 갱신한다.
