# ACCEPTANCE — 수용 기준 (시험의 정본)

> 이 문서가 "다 됐다"의 기준이다. Playwright 시험은 **이 문서만 보고** 구현과 독립적으로 쓴다.
> 시험 제목은 반드시 ID로 시작한다: `test('S4-13 예시 구직자 A × OO소프트 = 질문 5개와 유형 순서', …)`
> 화면 문구·접근성 이름은 아래 「정확한 문구」를 글자 그대로 쓴다. 구현이 이 문구를 바꾸면 시험이 깨지는 게 맞다.
> 범위 표시: **[M]** Must · **[S]** 밤샘 범위에 넣은 Should · **[R]** 1차 면접 정리(복기) 최소판. 시험 환경은 `vite build --mode mock` + `vite preview` (가짜 응답 모드, 서버 함수 없음).
> S4는 **단계형**이다: 1차 면접 준비에는 업무 질문만 주고, 처우 질문은 1차 면접을 정리한 뒤 최종 면접 단계에서 준다(근거: 「추가 개발 - 1차 면접 복기와 최종면접 맞춤 질문」 1절).

## G — 공통

- **G-01 [M]** 모든 경로(`/mypage/applications`, `/mypage/resume`, `/jobs`, `/jobs/:id`, S4 각 단계, `/about-ai`, 404)에 시연 띠 두 문구가 보인다.
- **G-02 [M]** 어느 화면에도 "공식 전자정부 누리집", "누리집입니다" 문구가 없다.
- **G-03 [M]** 주 메뉴에 다섯 항목이 있다. "채용정보" → `/jobs`. 나머지를 누르면 "시연 범위 밖 메뉴예요" 알림이 뜨고 주소가 바뀌지 않는다.
- **G-04 [M]** 마이페이지 화면에서 왼쪽 메뉴의 두 링크가 동작하고, 현재 화면 링크에 `aria-current="page"`.
- **G-05 [M]** 경로 표시의 마지막 항목이 화면 제목과 같다(S1·S2·S4).
- **G-06 [M]** 문서 제목이 `<화면 제목> | 고용24 (시연)` 형식이다.
- **G-07 [M]** 데스크톱(1440×900)과 휴대폰(375×812) 두 폭에서 모든 경로의 가로 스크롤이 없다(`scrollWidth <= innerWidth`).
- **G-08 [M]** 모든 경로를 주소로 바로 열거나 새로고침해도 화면이 나온다. 없는 주소는 404 화면.
- **G-09 [M]** 모든 경로에서 콘솔 오류(`console.error`, 처리 안 된 예외)가 0건.
- **G-10 [M]** 모든 경로에서 axe 검사 `critical`·`serious` 위반 0건.
- **G-11 [M]** 화면 어디에도 실제 개인정보 모양이 없다: 이메일은 `@example.com`만, 전화번호는 `010-0000-0000`만.
- **G-12 [M]** "시연 도구" → "시연 초기화"를 누르면 지원 내역·선택·결과·안내 띠 닫힘 상태가 모두 처음으로 돌아간다.
- **G-13 [M]** 브라우저 저장소가 막혀도(`localStorage` 접근 시 예외) 화면이 깨지지 않고 S1→S4③ 흐름이 돈다.

- **S4-13 [M]** A로 채운 뒤 "질문 만들기" → `?step=3`, 만드는 중 문구가 보였다가 "1차·기술 면접 질문"에 질문 5개. 유형 칩 순서: 충돌 확인, 충돌 확인, 기회 확인, 기회 확인, 깊이 확인. 1번 질문 문장에 "상주" 포함. 5번 질문에 "경험 포함" 칩과 "FastAPI" 포함.

- **S4-15 [M]** 1차 결과 화면에는 처우 질문(연봉·수당·근무시간 협의 문장)과 "처우 확인" 칩이 없다. 대신 "1차 면접을 다녀오면" 문구가 든 다음 단계 상자가 있다.
- **S4-16 [M]** (주)△△커머스 + 라디오 "1차·기술 면접" + 예시 구직자 A: 어떤 질문에도 "공고에 고객사 상주" 문구가 없고, 고객사 상주 개발 질문의 유형 칩은 "충돌 예방".
- **S4-17 [M]** `?apiFail=1`로 질문 만들기 → "미리 검수한 문장" 안내가 보이고, 질문 5개가 나오며 각 질문에 "검수 문장" 라벨. 이때도 S4-13과 같은 유형 순서.
- **S4-18 [M]** 질문의 "근거 보기" → `?step=1`로 가고 해당 `<mark>`에 `data-active="true"`.
- **S4-19 [M]** "선택 바꾸기" → `?step=2`, 고른 카드·경험이 그대로 있다.
- **S4-20 [M]** ③에서 새로고침해도 같은 질문이 그대로 보인다(브라우저 저장).
- **S4-21 [M]** "전체 복사" → 클립보드에 질문 5개 문장이 모두 들어 있다.
- **S4-22 [S]** "면접에 들고 갈 한 장 인쇄" → `window.print` 호출.
- **S4-23 [M]** "AI로 다시 만들기" → 만드는 중 문구가 다시 보였다가 질문 5개.

## R — 1차 면접 정리 → 최종 면접 질문 [R]

근거 설계: 「추가 개발 - 1차 면접 복기와 최종면접 맞춤 질문」 최소판(10절). 가짜 응답 모드의 판정은 정해 둔 예시 세트(아래 R-04)만 정확히 맞추고, 그 밖의 입력은 단순 규칙(구체적 → 확인됨, 모호 → 아직 모름, 못 물음 → 아직 모름, "회사가 먼저 설명해 줬어요" → 확인됨)으로 처리한다. "기대와 다름" 판정은 실제 LLM 몫이다.

- **R-01 [R]** S4-13 결과의 "면접 다녀왔어요" → 라디오 "최종 면접·처우 협의"로 바뀌고 단계 "1차 면접 정리"로 이동, 1차 질문 5개가 목록으로 보인다.
- **R-02 [R]** 질문마다 "물어봤어요"/"못 물어봤어요". "물어봤어요"면 "들은 답"과 "구체적이었어요"/"모호했어요"가, "못 물어봤어요"면 "못 물은 이유" 선택 상자(5개 선택지)가 나타난다.
- **R-03 [R]** "회사가 물어본 업무" 체크 17개와 "면접 분위기" 라디오 3개가 있다. 하나도 정리하지 않으면 "최종 질문 만들기" 비활성.
- **R-04 [R]** 예시 구직자 A × (주)OO소프트 1차 결과에서 "시연 도구" → "1차 면접 다녀온 것으로 채우기":
  - 고객사 상주 개발: 물어봤어요 · "프로젝트마다 달라서요" · 모호했어요
  - 기존 시스템 유지보수: 물어봤어요 · "유지보수가 7할쯤 되고 신규는 프로젝트 들어갈 때만요" · 구체적이었어요
  - 서비스 구조 설계: 물어봤어요 · "설계 리뷰에 신입도 들어가고 작은 기능은 직접 설계해요" · 구체적이었어요
  - DB 테이블 설계: 못 물어봤어요 · 시간이 없었어요
  - 신규 API 개발: 물어봤어요 · "수습 끝나면 작은 API부터 맡겨요" · 구체적이었어요
  - 회사가 물어본 업무: 장애 대응·온콜 · 면접 분위기: 압박이 있었어요
- **R-05 [R]** R-04 뒤 "최종 질문 만들기" → "최종 질문 받기" 단계, 소제목 "최종 면접·처우 질문". 요약: 확인됨 2 · 기대와 다름 1 · 아직 모름 2 · 회사가 먼저 물은 것 1. 첫 질문 유형 "다시 확인"이고 문장에 "상주" 포함. "처우 확인" 질문 3개 이상. 서비스 구조 설계·신규 API 개발 질문은 없다(확인됨이라 빠짐). 질문은 8개 이하.
- **R-06 [R]** 최종 질문 어디에도 1차 면접관 말 인용 표현("아까", "하셨는데", "말씀하신")이 없고, 분위기가 "압박이 있었어요"이므로 질문 1개 이상이 완충 문장("여쭤도 될까요")을 포함한다.
- **R-07 [R]** S1 2행 "최종 면접 준비" → "1차 면접 정리" 단계에 그 지원 건의 1차 질문 5개가 이미 있다(시드에 1차 결과 포함).
- **R-08 [R]** 1차 결과가 없는 지원 건(S1 3행)에서 라디오를 "최종 면접·처우 협의"로 바꾸면 "먼저 1차 면접 질문을 만들어 주세요"와 버튼 "1차 면접 질문 만들기"가 보인다.
