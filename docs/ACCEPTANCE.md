# ACCEPTANCE — 수용 기준 (시험의 정본)

> 이 문서가 "다 됐다"의 기준이다. Playwright 시험은 **이 문서만 보고** 구현과 독립적으로 쓴다.
> 시험 제목은 반드시 ID로 시작한다: `test('S4-13 예시 구직자 A × OO소프트 = 질문 5개와 유형 순서', …)`
> 화면 문구·접근성 이름은 아래 「정확한 문구」를 글자 그대로 쓴다. 구현이 이 문구를 바꾸면 시험이 깨지는 게 맞다.
> 범위 표시: **[M]** Must · **[S]** 밤샘 범위에 넣은 Should · **[R]** 1차 면접 정리(복기) 최소판. 시험 환경은 `vite build --mode mock` + `vite preview` (가짜 응답 모드, 서버 함수 없음).
> S4는 **단계형**이다: 1차 면접 준비에는 업무 질문만 주고, 처우 질문은 1차 면접을 정리한 뒤 최종 면접 단계에서 준다(근거: 「추가 개발 - 1차 면접 복기와 최종면접 맞춤 질문」 1절).

- **G-01 [M]** 모든 경로(`/mypage/applications`, `/mypage/resume`, `/jobs`, `/jobs/:id`, S4 각 단계, `/about-ai`, 404)에 시연 띠 두 문구가 보인다.

- **G-06 [M]** 문서 제목이 `<화면 제목> | 고용24 (시연)` 형식이다.

### AS — AI API 명세와 연결

- **AS-01 [M]** `docs/API-SPEC.md`가 있다. 맨 위에 이 문서로 할 일(AI 담당이 만들 호출 3가지 `POST /v1/first-questions` · `POST /v1/final-judgements` · `POST /v1/final-questions`), 시간 제한, 가장 큰 위험(근거 인용 규칙)이 있다. 대상 독자는 AI 담당(우리 레포 코드를 모르는 사람)이다.
- **AS-02 [M]** 화면 입력 → 요청 값 표가 있다. 1차: 지원 건 → `wantedAuthNo`, ② "기대돼요"·"걱정돼요"·"모르겠어요" → `picks[].pref`(`want`·`avoid`·`unsure`), 경험 한 줄(100자) → `experience`, 경험을 붙일 카드 → `picks[].has_exp`. 최종: "물어봤어요"·"못 물어봤어요" → `review.asked`·`review.not_asked`, 들은 답(100자) → `heard`, "구체적이었어요"·"모호했어요" → `clarity`, 못 물은 이유 5개 → `reason`, 회사가 물어본 업무 → `received`, 면접 분위기 → `impression.mood`. 그리고 우리 서버가 이 값을 AI 요청(공고 원문 `posting`, 질문 항목 `items`)으로 바꾸는 방법이 있다.
- **AS-03 [M]** (단위 시험) `docs/api-examples/`에 예시 JSON 6개(`first-request` · `first-response` · `final-judgements-request` · `final-judgements-response` · `final-questions-request` · `final-questions-response`, 예시 A × (주)OO소프트, 최종은 R-04 예시 세트). 요청 예시는 우리 서버가 실제로 만드는 값과 같고(시험이 코드로 만들어 비교), 응답 예시는 우리 검사(validate)를 통과한다. 다시 만드는 명령이 README에 있다.
- **AS-04 [M]** 「응답 규칙」 절: JSON만(설명 글 없음) · 항목의 `card_id`·`key`를 그대로 돌려줌 · 순서·개수를 바꾸지 않음 · 근거 인용(`evidence.quote`, 문장 속 '…')은 공고 원문 글자 그대로 · 공고에 없는 업무를 있다고 전제하지 않음 · 금지어(나이·결혼·출신 등) · 1차 면접관 말 인용 금지("아까" "하셨는데" "말씀하신") · 길이 · 문체(서술 "…습니다", 질문 "…인가요?", D-179) · 판정 `basis`에 들은 답을 옮기지 않음. 「실패 처리」 절: 문항 하나가 틀리면 그 문항만 검수 문장, 전체 오류·시간 초과면 모두 검수 문장(최종 판정은 단순 규칙). 오류 응답 형식 `{ "error": { "code", "message" } }`와 HTTP 상태.
- **AS-05 [M]** 「공통」 절: 인증 `Authorization: Bearer <AI_API_KEY>`, 주소 환경변수 `AI_ENDPOINT`, 시간 제한(우리 서버는 9초에 끊음 — 1차는 8초 안, 최종은 판정 + 문장 합계 9초 안), 개인정보(경험 한 줄·들은 답은 AI 쪽에서도 저장·기록하지 않음, 최종 문장 호출에는 들은 답을 보내지 않음), UTF-8 JSON, 버전 경로 `/v1`.
- **AS-06 [M]** 부록 2개: (A) 화면 → 우리 서버 `POST /api/questions` 요청·응답(지금 계약 그대로), (B) 공고 분석 데이터 형식 — AI 파이프라인이 미리 만들어 `data/analysis/<wantedAuthNo>.json`으로 넣는 형식(필드, 인용 규칙, 넣은 뒤 확인하는 시험 명령). 화면은 이 파일을 읽기만 한다.
- **AS-07 [M]** (단위 시험) `LLM_PROVIDER=remote`이면 서버가 `AI_ENDPOINT`의 세 주소를 명세대로 부른다. 가짜 fetch로: (a) 정상 응답 → `source: "ai"` (b) 모양이 틀린 항목만 검수 문장 (c) 시간 초과·5xx·JSON 아님 → 모두 검수 문장, 최종 판정은 단순 규칙 (d) 보낸 본문이 예시 JSON과 같은 모양 (e) `Authorization` 머리글. 키는 `api/`에서만 읽고 `dist/`에 `AI_API_KEY` 값이 없다. 기본값(가짜 응답 모드)과 배포 설정(`vercel.json` `build:mock`)은 그대로다.
- **AS-08 [S]** README에 「실제 AI 연결」 절: 환경변수 3개(`LLM_PROVIDER` · `AI_ENDPOINT` · `AI_API_KEY`), Vercel에 넣는 곳, 가짜 응답 모드에서 실제 모드로 바꾸는 순서, 명세 문서 링크.

### RS — 결과 화면 버튼 정리 (1차·최종 ③)

- **RS-01 [M]** 1차·최종 ③ 질문마다 "복사"·"면접에서 쓸 것 같아요" 버튼이 없다. 질문마다 남는 것은 "왜 이 질문인가요" 펼침과 그 안 "근거 보기" 링크다. "더 알아볼 질문"에도 복사 버튼이 없다.
- **RS-02 [M]** 데스크톱(1440×900 · 1366×657): "전체 복사"와 "면접에 들고 갈 한 장 인쇄"가 오른쪽 상자 안에 있다(화면 전체에서 각 하나). 1차 아래 고정 바에는 버튼 "면접 다녀왔어요" 하나만 있다. 최종 ③에는 아래 고정 바가 없다.
- **RS-03 [M]** 오른쪽 상자가 질문 아래로 쌓이는 폭(1100px 이하)과 휴대폰 375×812에서는 "전체 복사"·"면접에 들고 갈 한 장 인쇄"가 첫 질문보다 위에 있다(버튼 아래끝 ≤ 1번 질문 위끝). 가로 넘침이 없다.
- **RS-04 [M]** 인쇄·전체 복사 순서는 화면 순서 그대로다. 1차 전체 복사 글은 질문 5개 뒤에 소제목 "더 알아볼 질문"과 그 문장들(더 알아볼 질문이 없으면 소제목도 없음). 인쇄 한 장에는 더 알아볼 질문이 없다(Q-02 그대로). 최종 복사 글은 소제목 두 개 아래로 나뉜다(V-02 그대로).
- **RS-05 [S]** ③ 오른쪽 상자 안내에 "면접에서 쓸 것 같아요" 문장이 없고 "면접에서는 보통 한두 개만 물을 수 있어요"는 남는다. 화면 어디에도 "면접에서 쓸 것 같아요"가 없다(/about-ai 포함).
- **RS-06 [S]** 버튼 줄이 빠진 질문 카드에 빈 여백이 없다(질문 문장 바로 아래 "왜 이 질문인가요"). 1440×900 ③ 첫 화면에 1번 질문 전체와 2번 머리 이상(F-02 그대로).

### HP — 카드 높이와 도움말 (②)

- **HP-01 [M]** ② 카드마다 고른 것과 관계없이(고르기 전·기대돼요·걱정돼요·모르겠어요) 버튼 "<카드 이름> 도움말"(보이는 글 "도움말")이 보인다. 카드 안에서 펼쳐지는 영역은 없다("예를 들면" 펼침 버튼 없음).
- **HP-02 [M]** "도움말"을 누르면 팝업(`role="dialog"`, 이름 "<카드 이름> 도움말")이 뜬다. 안에 소제목 "예를 들면"과 그 카드 예시 2개(`cards.backend.json` `examples`), 낯선 말 풀이 1~3개(`aria-label` "용어 풀이"). 데스크톱은 버튼 가까이(버튼을 가리지 않고 팝업 전체가 화면 안), 휴대폰(767px 이하)은 화면 아래에서 올라오는 시트(폭 전체, 아래끝 = 화면 아래끝).
- **HP-03 [M]** 열리면 초점이 팝업 안으로 간다. "닫기"·Esc·팝업 바깥 누르기로 닫히고, 닫히면 초점이 그 "도움말" 버튼으로 돌아온다. 한 번에 팝업 하나만 열린다.
- **HP-04 [M]** "모르겠어요"를 골라도 팝업이 저절로 열리지 않는다. 고르기·팝업 열고 닫기로 어떤 카드의 높이도 바뀌지 않는다.
- **HP-05 [M]** 카드가 한 줄에 둘 이상인 폭(768px 이상): 보이는 카드 높이가 모두 같다(±1px, "5개 더 보기"로 17개를 다 펼친 뒤 포함). 휴대폰(한 줄에 하나)은 제 내용 높이. F-03(1440×900 첫 화면 카드 4개)과 V-06(②로 옮긴 직후 카드 수) 그대로.
- **HP-06 [S]** 높이를 맞추려고 카드 설명 글을 줄였다면(말줄임) 그 카드 도움말 팝업 맨 위에 설명 전체가 있다.
- **HP-07 [M]** 키보드만으로 열고 닫을 수 있다(Tab → Enter/Space → Esc). 팝업이 열린 상태에서 axe 위반이 없다.

### LD — 공고 분석 로딩과 형광펜 (①)

- **LD-01 [M]** S1에서 면접 준비 버튼(이름은 D-197 규칙대로)이나 "바로 해 보기"로 ① 공고 확인에 처음 들어가면 ① 내용보다 로딩 화면(`role="status"`)이 먼저 보인다: 제목 "AI가 분석한 공고를 펼치고 있어요", 단계 3줄 "공고 원문 확인" "업무 카드와 맞춰 보기" "확인할 곳 표시"가 차례로 켜지고, 이 공고 분석의 근거 인용 최대 4개가 차례로 나타난다. 고용24 틀(시연 띠·헤더·주 메뉴·왼쪽 메뉴·경로·S4 머리·단계 표시)은 그대로다.
- **LD-02 [M]** 로딩은 1.5~2.5초 뒤 저절로 ①로 바뀌고 초점은 ① 제목으로 간다. 같은 지원 건은 두 번째부터 로딩 없이 바로 ①이다(단계 표시로 돌아올 때, ③ "근거 보기"(`?card=`)로 올 때, 새로고침 포함). "시연 초기화" 뒤에는 다시 보인다.
- **LD-03 [M]** 로딩 뒤 ①에서 형광펜이 문서 순서대로 차례로 칠해진다. 칠하기 전 `<mark data-drawn="false">`, 칠한 뒤 `data-drawn="true"`. 첫 화면 형광펜은 로딩이 끝나고 2초 안에 모두 칠해지고, 화면 밖 형광펜은 스크롤해서 보일 때 칠해진다. 칠하는 모양은 왼쪽에서 오른쪽으로 채워지는 형광펜 긋기(한 개 약 0.4초, 간격 약 0.25초)이고, 다 칠한 모양은 지금 형광펜과 같다. 칠하는 중에도 형광펜 누르기·말풍선(F-04)이 된다. 처음 온 사람 안내가 켜져 있으면(7차, H3-r1-02) 안내가 떠 있는 동안에는 차례 칠하기를 멈추고, ① 안내 2단계 "형광펜"이 비추는 형광펜 하나만 그때 긋는다. 안내를 닫으면 그때 화면에 보이는 형광펜부터 다시 차례로 긋는다.
- **LD-04 [M]** 두 번째 방문(LD-02)과 "움직임 줄이기"(`prefers-reduced-motion: reduce`)에서는 로딩 없이 바로 ①이고 형광펜이 처음부터 `data-drawn="true"`다.
- **LD-05 [S]** 로딩 화면에 "분석하는 중"·"분석 중"처럼 지금 분석한다는 말이 없다(공고 분석은 AI 파이프라인이 미리 만든 결과, D-219·/about-ai와 같은 말).
- **LD-06 [M]** 휴대폰 375×812에서 로딩 화면이 가로로 넘치지 않고 단계 3줄이 첫 화면에 보인다. 로딩 중·형광펜 칠하는 중에 axe 위반이 없다.

### TR — 처음 온 사람 안내 (스포트라이트)

- **TR-01 [M]** 처음 방문(저장값 없음) 때 첫 화면 S1 지원 현황(`/`도 여기로 감)에서 **서비스 안내**가 저절로 시작된다. 화면을 어둡게 하고 대상 하나만 밝게 비추며, 옆에 설명 상자(`role="dialog"`, `aria-modal="true"`, 제목·설명·단계 "N/M"·"이전"·"다음"·"건너뛰기", 마지막 단계 "시작하기"). 6~8단계로 이 사이트에 만들어진 기능을 모두 소개한다: 시연 사이트 소개 · 주 메뉴 "채용정보"(공고를 보고 입사지원하면 지원 현황에 더해짐) · 지원 현황 표 · 면접 준비 버튼(공고 확인 → 기대·걱정 고르기 → 1차 질문) · 1차 합격 지원 건의 버튼(1차 면접 정리 → 최종 면접·처우 질문) · 이력서(경험 한 줄) · 시연 띠 "시연 도구"(예시로 채우기·시연 초기화·안내 다시 보기). 설명 글에 "채용정보" "지원 현황" "1차" "최종" "이력서" "시연 도구"가 모두 나온다.
- **TR-02 [M]** 다른 화면에 처음 들어가면 그 화면 안내(2~3단계)가 저절로 시작된다: 채용정보 목록, 공고 상세(입사지원 → 지원 현황), 이력서, 면접 준비 ① 공고 확인(로딩·형광펜이 끝난 뒤), ② 기대·걱정 고르기, ③ 1차 질문, 1차 면접 정리, 최종 ③. /about-ai와 없는 주소에는 안내가 없다.
- **TR-03 [M]** 한 번 안내한 화면(끝까지 봤거나 "건너뛰기"·Esc로 닫음)은 다시 들어와도(새로고침·새 탭 포함, 이 브라우저 기준) 안내가 뜨지 않는다. 시연 도구 "시연 초기화"를 누르면 모든 화면의 본 기록이 지워져, 안내를 끄지 않았으면 S1에서 서비스 안내가 다시 시작된다("안내 끄기"는 그대로, TR-05).
- **TR-04 [M]** S1 안내 띠 "이용 안내 다시 보기"와 시연 도구 "안내 다시 보기"는 서비스 안내를 처음부터 다시 띄운다(다른 화면 안내 기록은 그대로).
- **TR-05 [M]** 시연 도구 "안내 끄기"를 누르면 어느 화면에서도 안내가 저절로 뜨지 않고 버튼이 "안내 켜기"가 된다. 주소에 `?tour=off`를 붙여 들어와도 같다(이 브라우저에 저장). "시연 초기화"는 끄기를 풀지 않는다(7차, H3-r1-03 — 발표 중 초기화해도 안내가 뜨지 않게). 끈 채 초기화하면 알림 "시연을 처음 상태로 되돌렸어요. 안내는 꺼진 채예요".
- **TR-06 [M]** 안내가 뜨면 초점이 설명 상자로 가고, Tab은 상자 안에서만 돈다. Esc = "건너뛰기". 닫히면 초점이 안내 전 자리(없으면 화면 제목)로 돌아간다. "다음"을 누르면 대상이 화면 안으로 스크롤되고, 비춘 대상과 설명 상자가 겹치지 않는다. 안내 중에는 뒤 화면이 눌리지 않는다. 안내가 떠 있는 상태에서 axe 위반이 없다.
- **TR-07 [M]** 휴대폰 375×812 · 데스크톱 1440×900 · 1366×657의 모든 단계에서 설명 상자 전체가 화면 안에 있다(가로 넘침 없음). 휴대폰은 상자가 화면 아래 시트이고 비춘 대상은 시트 위에 보인다. 대상이 그 폭에서 숨어 있으면(접힌 메뉴 등) 보이는 다른 대상이나 대상 없는 가운데 상자로 바꾼다(빈 구멍·화면 밖 구멍 없음).
- **TR-08 [S]** 안내는 다른 것과 겹쳐 뜨지 않는다: 시연 도구 메뉴가 열려 있거나 도움말 팝업이 떠 있거나 ① 로딩 중이면 끝난 뒤 시작한다. "움직임 줄이기"면 비춤 이동·상자 등장에 움직임이 없다.
- **TR-09 [M]** 시험 전용 스위치: localStorage `rq:test:tour-off` = `"1"`이면 안내가 저절로 뜨지 않는다("시연 초기화"로 지워지지 않는 키). 기존 시험은 이 스위치를 켠 채 돌고 결과가 바뀌지 않는다. TR 시험만 끄고 돈다.
