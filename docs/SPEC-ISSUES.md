# SPEC-ISSUES — 시험과 수용 기준이 어긋난다고 본 것

> 형식: `ID · 이유 · 제안 · 적은 에이전트`. 개발자는 e2e/를 고치지 않고 여기에 적는다. QA가 판정하고, 시험 쪽이 틀렸으면 수정 개발자가 고친다.

- API-05(e2e `quality.spec.ts` "API-05 화면 쪽") · PLAN은 API-05를 M3 범위로 두는데, 시험이 `makeFinalQuestions`(R-04 "1차 면접 다녀온 것으로 채우기"·"최종 질문 만들기", M5)를 거쳐서 M3만으로는 통과할 수 없다(시연 도구 버튼을 기다리다 시간 초과). 시험이 보는 내용(콘솔 로그에 경험 한 줄·들은 답 원문 없음)은 ACCEPTANCE와 맞다 · M3 판정은 단위 시험(`api/questions.test.ts`)으로 하고 e2e API-05는 M5 뒤에 판정. 또는 1차 흐름(`makeFirstQuestions`)만 거치는 경험 한 줄 로그 검사를 따로 나누기 · Claude(M3)
- API-05(ACCEPTANCE 문구) · "응답 어디에도 … 경험 한 줄 원문이 없다"를 글자 그대로 읽으면 S4-13(5번 질문에 "FastAPI"·"경험 포함")과 부딪힌다. 검수 문장은 카드 질문 틀의 `{anchor}`에 경험을 그대로 붙이므로(데이터 `anchor_rule`) 대체 결과에는 경험 원문이 들어간다 · 문구를 "응답에 요청 값(경험 한 줄·들은 답)을 되돌려 주는 필드가 없고, 로그에는 없다"로 고치기. 지금 구현은 이 해석(D-043) · Claude(M3)
