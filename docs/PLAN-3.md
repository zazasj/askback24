## T1 AI API 명세와 연결 (AS-01~08)

정한 것(세진 10-25): 1-1 우리 서버(Vercel 함수)가 AI 담당 서버를 부르는 경계 · 1-2 지금 구조 — 질문 순서·유형·근거는 우리 규칙, AI는 질문 문장 쓰기와 최종 들은 답 판정. **공고 분석은 AI 파이프라인이 따로 있고, 그 결과를 미리 만들어 우리 쪽(`data/analysis/`)에 저장한다** · 1-3 최종은 명세 하나에 호출 두 번(판정 → 우리 규칙이 순서 결정 → 문장) · 1-4 연결 코드와 계약 시험까지 · 1-5 레포 md(볼트 사본은 아침에 메인 세션이 만든다).

- `docs/API-SPEC.md`: 쓰기 전에 `D:/Source/S2-CMS-AgentHub/skills/doc-design/SKILL.md`와 `types/design.md`를 Read 한다. 읽는 사람은 **AI 파이프라인 담당(형원, 우리 레포 코드를 모름)**. 형원은 온보딩 문서 `D:/Obsidian/50_대외활동/2026_고용24_AI해커톤/개발준비/질문 생성 파이프라인.html`을 이미 받았으니 읽기만 하고, 같은 낱말·단계 이름을 쓰고 서로 다른 말이 있으면 명세가 맞게(코드 기준) 적은 뒤 다른 점을 보고서에 남긴다. 맨 위에 할 일·시간 제한·가장 큰 위험(인용 규칙). 그다음 흐름 그림(화면 → `/api/questions` → 규칙 → AI 호출 → 검사·대체 → 화면, mermaid 또는 표), 공통, API 1(1차), API 2(최종: 판정·문장), 응답 규칙, 실패 처리, 부록 A(`/api/questions`), 부록 B(공고 분석 데이터 형식).
- 호출 3가지와 형식은 `shared/providers/types.ts`를 그대로 따른다(키 이름을 바꾸지 않는다):
  - `POST {AI_ENDPOINT}/v1/first-questions` — 본문 `FirstDraftInput` → 응답 `{ "questions": Draft[], "model"?: string }`
  - `POST {AI_ENDPOINT}/v1/final-judgements` — 본문 `JudgeInput` → 응답 `{ "judgements": Judgement[], "model"?: string }`
  - `POST {AI_ENDPOINT}/v1/final-questions` — 본문 `FinalDraftInput` → 응답 `{ "questions": FinalDraft[], "model"?: string }`
  - 오류: HTTP 4xx·5xx + `{ "error": { "code": string, "message": string } }`
- 시간: 서버 기준 `PROVIDER_TIMEOUT_MS` 9초(최종은 판정·문장이 한 마감을 나눠 씀, `shared/generate.ts`). 명세에는 "1차 8초 안, 최종 판정 3초·문장 5초 안 권장"으로 적는다.
- 예시 JSON(`docs/api-examples/*.json` 6개)은 손으로 쓰지 않는다: 캡처 공급자로 실제 요청을 받아 쓰는 스크립트(`npm run api:examples`)를 만들고, 단위 시험이 지금 코드가 만드는 값과 파일이 같은지 비교한다(AS-03). 응답 예시는 가짜 공급자 출력이고 `validate`를 통과해야 한다.
- 연결 코드: `shared/providers/remote.ts`(`LLM_PROVIDER=remote`), `api/_lib/provider.ts`·`api/questions.ts`에 `AI_ENDPOINT`·`AI_API_KEY`. 응답 모양 검사(필수 필드·타입)에서 틀린 항목은 버린다 → `generate`가 그 항목만 검수 문장으로 대신한다. 엔노이아 자리는 지우지 않는다. `vercel.json`(`build:mock`)과 기본 가짜 응답 모드는 그대로(배포 전환은 세진이 정함).

정한 것: 4-1 사실인 문구 "AI가 분석한 공고를 펼치고 있어요"(공고 분석은 AI 파이프라인이 미리 만든 결과 — 1-2 세진 설명과 D-219가 같은 말) · 4-2 지원 건마다 처음 한 번 · 4-3 약 2초 · 4-4 왼쪽에서 오른쪽으로 칠하는 형광펜 긋기.

- 형광펜: 로딩 뒤 처음 보는 ①에서만. `<mark data-drawn>`을 false로 그렸다가 문서 순서대로 true로(배경 그라디언트 크기 0→100%, 줄 넘김은 `box-decoration-break: clone`). 화면 밖은 IntersectionObserver로 보일 때. 다 칠한 모양은 지금과 같아야 한다(색·켜진 형광펜 모양 그대로). 두 번째부터는 처음부터 true.

## T5 처음 온 사람 안내 — 스포트라이트 (TR-01~09)

정한 것: 5-1 **첫 화면(S1)에서는 사이트에 만들어진 기능 전체를 소개하는 서비스 안내**, 그 뒤 다른 화면에 처음 들어가면 그 화면 안내. **한 번 안내한 화면은 다시 띄우지 않고, 시연 도구 "시연 초기화"를 누르면 모두 다시 뜬다**(세진) · 5-2 처음 방문 자동 + "이용 안내 다시 보기" · 5-3 시연 도구 "안내 끄기"와 `?tour=off` · 5-4 직접 만들기.

- 부품: 앱 전체에 하나 있는 안내 틀 + 화면마다 단계 목록을 넘기는 composable. 대상은 `data-tour="…"` 속성으로 찾는다(시험은 이 속성을 쓰지 않는다).
- 비춤: 화면 전체 어두운 막 + 대상 둘레만 밝게(대상 크기 + 여백, 화면 바뀜·스크롤·크기 바뀜에 다시 잼). 막을 눌러도 아무 일 없음. "다음"이면 대상을 화면 안으로 스크롤(위·아래 고정 바를 피해).
- 설명 상자: `role="dialog"` `aria-modal="true"`, 제목·설명, "N/M", "이전"·"다음"·"건너뛰기", 마지막 "시작하기"(S1)/"닫기". 초점 가두기, Esc = 건너뛰기, 닫히면 초점을 돌려놓는다. 휴대폰은 아래 시트, 대상은 시트 위에.
- 대상이 그 폭에서 안 보이면(크기 0·숨김·접힌 메뉴) 화면마다 정한 다른 대상 또는 대상 없는 가운데 상자.
- 저장: `rq:v1:tour` = `{ seen: 화면키[], off: boolean }`. "시연 초기화"(`clearAllKeys`)가 지우는지 확인하고, 초기화 뒤 S1으로 가면 서비스 안내가 다시 시작되게 한다. 시연 도구 "안내 다시 보기"(지금 버튼)는 안내 띠와 함께 서비스 안내도 다시 띄운다. S1 안내 띠에 "이용 안내 다시 보기". 시연 도구에 "안내 끄기"↔"안내 켜기". `?tour=off` → `off: true` 저장.
- 순서 맞추기: 시연 도구 메뉴·도움말 팝업·① 로딩·형광펜 칠하기가 끝난 뒤 시작한다.
- 화면과 단계(초안 — 글은 짧은 해요체로 다듬는다):
  - **S1 서비스 안내(6~8단계)**: ① 시연 사이트 소개(가운데 상자: 이미 지원한 공고로 면접에서 물어볼 질문을 준비하는 서비스) ② 주 메뉴 "채용정보" — 공고를 보고 입사지원하면 지원 현황에 더해져요 ③ 지원 현황 표 ④ 맨 위 지원 건 면접 준비 버튼 — 공고 확인 → 기대·걱정 고르기 → 1차 질문 5개 ⑤ 1차 합격 지원 건 버튼 — 1차 면접 정리 → 최종 면접·처우 질문 ⑥ 왼쪽 메뉴 이력서 — 경험 한 줄을 질문에 붙여요 ⑦ 시연 띠 "시연 도구" — 예시로 채우기·시연 초기화·안내 다시 보기 ⑧(선택) "바로 해 보기"
